As Frontend Engineer and SEO Specialist:
- Internal links lack the trailing slash. Links point to /studio-foto-fe/galeria, but the canonical URL (and what GitHub Pages serves) is /galeria/. Every link a crawler follows causes a 301 redirect, and the link signals point at a URL that isn’t canonical. Use to="/galeria/" (or a helper) everywhere, including the logo and footer links.
- Photos are missing from the prerendered HTML on Portfolio and session pages. PhotoMasonry places photos only after measuring them in the browser, so the static HTML has no gallery <img> tags at all. Portfolio, /galeria/sesja-slubna-lazienki-krolewskie/ and /galeria/sesja-rodzinno-brzuszkowa/ each contain only the logo. For a photographer, Google Images is a real source of traffic. The image sitemap helps, but images Google can find in the page itself rank much better. Possible fix: store each photo’s width and height at build time (vite-imagetools can output metadata, or use a small script). Then the first batch can be rendered on the server, and the layout no longer needs measuring. This also fixes layout shift.
- The favicon is a data URI. Google’s search-result favicon needs a crawlable file URL (a multiple of 48×48 px). Add public/favicon.ico or favicon.svg, a 180 px apple-touch-icon.png and a site.webmanifest. In mobile results the favicon sits next to your name, so it affects click-through.
- in mobile view, at start page when scrolling down to text, images are been zoomed.
- Contact: mark the date field as optional and add a “Miejsce wesela” field. That’s better for conversion, not rankings, and conversion is what SEO is ultimately for.
